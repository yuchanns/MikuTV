# 插件架构设计

MikuTV 通过按种类划分的插件扩展功能。内容源插件提供视频服务、账号和网站操作；主题插件提供全局外观配置。两者共用插件管理与分发体系，分别遵循各自的声明和加载协议。内容页面继续使用[已确定的 visual](visual/)。

本文定义待实施的架构。当前工程已有 tvOS Hello World 基础，功能实施顺序见[任务拆分](implementation-tasks.md)。

## 1. 范围与原则

- 宿主使用 Go、MyGo 原生 UI 和现有 tvOS 平台补丁；运行时使用 moejs 执行来源插件。
- 插件清单用 `kind` 区分 `source` 与 `theme`，公共包管理不依赖内容入口。按种类校验和加载，不为所有插件强制要求网站、账号、播放或 JS 入口。
- 先定义来源中立的内容源协议，入口配置、认证、内容和播放均通过协议提供；示例影视作为内置内容源插件实现，不进入宿主核心。
- 页面、网站协议和原生播放分别维护。页面不拼接网站请求，不解析网站响应，也不根据插件 ID 编写业务分支。
- 内容源输出数据与能力，宿主负责界面模板。所有入口共享同一套布局、卡片、焦点、详情、播放器和状态页，并使用当前全局主题。
- 从首个前端功能开始集中管理语义颜色，组件不散写颜色常量；默认主题保持既定 visual，主题插件通过配置替换配色。
- 一项网站特有功能可以作为可选能力保留，不要求其他插件实现同名网站概念。
- 按实际功能增量扩展协议，先完成示例影视的登录、推荐、详情和播放闭环。

本计划包含插件种类、收录、分发、安装更新、来源运行时、能力识别、入口隔离及主题格式。先实施内容源闭环；主题格式在此确定，主题包的实际加载与选择在外观功能中实现。

## 2. 分层与依赖

```text
Go UI -> Application -> Typed Provider Services -> Plugin Runtime -> Source Plugin
                     -> Native Player

Source Plugin -> Host HTTP / Storage / Secrets / Timers / Crypto
Native Player -> Host Resource Transport
Plugin Manager -> Package Store -> Source Loader / Theme Loader
Theme Plugin -> Validated Theme Configuration -> Go UI
```

| 位置 | 职责 | 边界 |
|---|---|---|
| `internal/ui` | visual 组件、页面呈现、遥控交互 | 调用应用层，接收统一页面状态与主题；不访问网站 API，不散写配色常量 |
| `internal/app` | 路由、入口会话、账号状态、异步任务与焦点恢复 | 协调服务和播放器，管理结果归属 |
| `internal/provider` | 统一模型、能力定义、类型化服务和错误 | 不依赖 UI，也不包含特定来源字段与端点 |
| `internal/plugin` | 公共清单、包管理、种类分派，以及内容源的 moejs 和协议适配 | 维护包身份、种类、版本与来源；内容源加载器把 JS 操作适配为 Provider 服务，主题不经过 JS 运行时 |
| `internal/theme` | 默认主题、语义颜色、主题文件校验与全局应用 | 消费主题数据，不依赖来源会话；向 UI 提供已解析的类型化配置 |
| `internal/player` | 原生播放、音视频轨道、播放状态与系统生命周期 | 消费播放计划；网站鉴权和播放地址解析交给插件 |
| `plugins/sample-source` | 示例内容源插件的登录、签名、网站请求和响应转换 | 使用统一插件协议，不操作 Go 视图或原生播放器 |
| `assets/plugins` | 随应用分发的固定版本插件包 | 记录构建来源、版本和包摘要，供统一运行时加载 |
| 独立插件仓库 | 对应种类的实现、配置与发布 | 发布统一格式的插件包，由宿主按种类加载 |

Go 调用方使用按领域划分的类型化服务，例如账号、目录、播放、评论、弹幕。JS 边界使用统一的数据协议和操作注册表，不让页面直接调用字符串 RPC 或处理任意 JSON。

内容源插件可用 TypeScript 开发并发布为 JS 模块；主题插件发布 JSON 配置。moejs 依赖固定到发布 tag，首轮以 `v0.1.1` 为接入基线，在实体 tvOS 上验证后使用。TV 运行时不依赖 Node、Bun、外部进程或网页窗口。

## 3. 插件、入口与会话

三个概念分别管理：

- 插件：带有明确种类的扩展包，以及安装、版本和启停状态。
- 内容入口实例：内容源插件加上用户配置；同一内容源可以对应多个独立配置实例。主题不生成内容入口。
- 账号会话：某个入口保存的账号和认证状态，独立于插件安装与启停状态。

入口选择只列出已安装且启用的 `source` 插件所提供的入口。示例影视随应用预装，首次启动无需下载即可选择；入口选择复用既有 visual 的卡片、列表和焦点样式。

主侧栏提供独立的「切换入口」项，用于选择不同内容源的入口。头像／账号入口负责当前内容源内部的账号切换，两者分别呈现。插件管理保留在设置框架内，面向所有插件种类，负责安装、启停、更新与卸载。

账号选择只展示当前入口保存的账号，并提供添加账号的操作。添加时进入所属插件的认证流程；取消不改变当前账号，成功后才切换。切换内容入口时恢复各自的账号、集合与浏览位置，不把另一入口的账号显示为当前账号。

入口选择页显示插件封面、名称、说明及当前入口。封面由插件的 `artwork.cover` 提供，宿主统一裁切与焦点样式；未配置或解码失败时回退到图标。移动焦点只浏览，确认选择后才切换；取消返回原页面并恢复原焦点。切换复用目标入口保存在本机的登录态，由所属插件校验或刷新，不能要求每次重新登录。

启动时恢复最近使用的可用入口；没有可恢复入口时展示选择页。插件支持匿名使用时可以继续浏览；登录过期只影响所属入口，取消认证后仍保留其他插件的登录态。

多个插件可以同时启用，当前界面一次使用一个入口。切换入口不会停用其他插件。切换时停止旧播放、取消旧请求与订阅，释放旧运行时，再恢复目标入口的路由、列表位置和焦点；不自动重播旧视频。

每个入口实例有独立的 HTTP 会话、插件存储、凭据、缓存和历史。需要用户身份的数据进一步按账号隔离；同插件内切换账号也使旧请求失效。游客状态独立保存，不自动归并到登录账号。全局外观偏好与入口数据分开保存。

停用或卸载当前入口所属插件时，关闭其任务并返回可用入口选择；没有可用入口时仍保留插件管理入口，不自动启用其他插件。目标不可用时提供选择和重试路径，不显示上一个入口的内容作为新入口结果。

每个异步请求关联入口、账号、请求参数和会话代次。晚到结果只能更新所属会话，不能覆盖当前入口。登录刷新和扫码轮询还需关联本次认证尝试，取消或换码后旧结果不得重新触发登录。

## 4. 插件声明与操作

公共清单描述身份、种类、协议版本和可选展示资源，再按种类声明专属字段。内容源示例：

```json
{
  "id": "example",
  "name": "Example",
  "kind": "source",
  "version": "0.1.0",
  "apiVersion": 1,
  "minAppVersion": "0.1.0",
  "main": "index.js",
  "artwork": {
    "cover": "assets/cover.png"
  },
  "authentication": {
    "methods": ["qrCode"]
  },
  "permissions": {
    "network": ["api.example.com"]
  },
  "capabilities": [
    "account.signIn",
    "catalog.browse",
    "catalog.item",
    "playback.resolve"
  ]
}
```

示例中的网络范围只说明清单形态，实际实现需列出该插件所需的 API 和资源主机。

`kind` 必填且属于已实现的种类；缺失、未知或当前宿主尚未支持的种类按协议不兼容处理，不能默认为内容源。种类属于插件身份的一部分，同一插件 ID 的更新不能改变种类。主题清单格式见第 7.1 节。

`artwork.cover` 是可选的包内相对路径，支持静态 PNG、JPEG 和 WebP，建议使用 2:1、1600×800 图片。图片随插件版本和包摘要一起发布，不依赖登录、脚本执行或外部下载。宿主按卡片边界居中裁切，显示名称、当前标记和焦点；插件不控制这些样式。安装时拒绝绝对路径、目录穿越及指向包外的资源，限制文件大小与解码尺寸；缺图或图片损坏不阻断插件功能，使用图标回退。

内容源加载时检查协议版本、声明与真实导出是否匹配。统一注册表将 `catalog.item` 等操作映射到 `getItem` 等 JS 导出函数；页面不参与这层映射。能力随对应功能实现而增加，不能提前宣称尚未实现的操作。

认证方式属于插件清单的一部分，取值必须来自宿主已实现的类型。首版只开放 `qrCode`；不支持账号密码表单或设备码，也不接受相应声明。声明不受支持的认证方式时，按协议不兼容处理，不能安装或启用。

账号、目录、播放是首个闭环所需服务。评论、弹幕、直播聊天、内容互动和消息等采用独立的可选服务，不把全部网站功能塞进一个必选接口。

## 5. 统一数据模型

| 模型 | 内容 |
|---|---|
| `MediaRef` | 入口实例、实体类型与插件内部的不透明 ID；入口归属由宿主补齐 |
| `MediaItem` | 视频、电影、剧集、单集、直播或集合的展示信息、创作者、进度和可用操作 |
| `Creator` | 创作者或频道资料及其内容入口，不强制使用 创作者这一网站概念 |
| `CollectionPage` | 栏目、分组、卡片、筛选条件和下一页游标 |
| `NavigationItem` | 栏目标题、宿主图标与目标页面或集合引用 |
| `ActionSpec` | 操作标识、展示类型、图标、当前状态与可用性 |
| `AuthChallenge` | 宿主已支持的认证挑战及其状态；首版为二维码、有效期与扫码进度 |
| `PlaybackPlan` | 媒体资源、轨道、请求上下文、有效期及播放能力 |

来源的内容标识、资源标识和分页参数均由插件解释。分页游标对页面保持不透明，筛选或入口变化时重新开始分页。

分 P、剧集和媒体库目录通过集合与子项表达，宿主根据内容类型和受支持的展示模板渲染。评论分页与直播聊天订阅分别建模，避免混淆两者的生命周期。

支持、快捷支持、追番等网站操作通过可选操作描述提供。宿主渲染统一的操作栏并派发操作，具体语义和请求属于插件。

## 6. 能力与功能显隐

| 层次 | 判断内容 | 界面行为 |
|---|---|---|
| 插件能力 | 插件声明且实际实现的服务 | 未实现则隐藏模块及其导航、按钮和焦点项 |
| 宿主能力 | 当前客户端具备的展示、输入和播放能力 | 不提供无法执行的操作或轨道选项 |
| 内容特性 | 当前内容是否适用评论、字幕、章节、拖动等 | 按内容组织模块，直播不显示点播专属控制 |
| 账号与内容权限 | 是否需要登录、会员或其他授权，内容是否限制操作 | 呈现登录引导或权限原因，不改写插件能力 |

插件如果不提供评论和弹幕，对应模块完全隐藏，剩余内容按同一套布局规则重新排列。如果插件支持评论，但当前视频关闭评论，则使用内容状态呈现原因。网络错误、限流和暂时无数据也不能被解释为插件不支持。

能力变化后需重新计算可聚焦元素；原焦点失效时移动到合理的相邻元素，不能停在隐藏控件上。

## 7. 页面与导航复用

内容源插件返回栏目、集合、内容和操作描述，宿主使用固定的原生模板：

- 入口选择与账号页。
- 栏目、卡片网格、列表、筛选与搜索。
- 视频、电影、创作者和剧集详情。
- 播放器及其轨道、章节和控制面板。
- 评论、弹幕、直播聊天与消息等可选模块。
- 加载、空态、错误、登录和权限状态。

内容源可以组合栏目和操作，不能提交任意 UI 脚本、HTML 或 CSS，也不能覆盖宿主配色。既有 visual 中的示例内容源页面是首个完整实现；其他来源通过数据和能力组合复用这些组件。

共享选择弹窗默认聚焦当前选项，没有已选项时聚焦第一个可操作选项；关闭使用普通次级按钮，不抢占初始焦点或铺满选项列表。评论、通知与聊天区域通过底色表达焦点，不添加沿圆角弯折的单侧强调线；选中、焦点和悬停仍分别呈现。

侧向面板采用推移正文的布局：左侧导航展开向右推移，右侧评论面板展开向左推移，关闭时恢复。平移不改变正文布局宽度，并保留页面滚动位置与焦点；左右区域使用同一横向布局，正文固定宽度且不收缩，由侧栏宽度过渡自然推开正文，避免另行同步正文位移动画。确认主导航后焦点进入正文并收起侧栏。侧栏展开时使用图标与品牌名横向组合，收起仅保留图标，图标锚点和菜单高度保持稳定。

### 7.1. 主题插件格式

主题插件采用与内容源相同的 `plugin.zip` 分发，根目录包含 `plugin.json` 和清单指定的 `theme.json`，可包含展示资源。主题只提供声明式配置，不包含执行入口，不声明内容源的认证、网络权限或服务能力。

主题 `plugin.json` 示例：

```json
{
  "id": "example-dark",
  "name": "Example Dark",
  "kind": "theme",
  "version": "0.1.0",
  "apiVersion": 1,
  "minAppVersion": "0.1.0",
  "theme": "theme.json",
  "artwork": {
    "cover": "assets/cover.png"
  }
}
```

`theme` 必须指向包内 JSON 文件，遵循与展示资源相同的路径边界。`main`、`authentication`、`permissions` 和 `capabilities` 不属于主题清单，声明时拒绝；公共安装器不要求主题具有 JS 导出。清单的 `apiVersion` 管理插件包协议，主题文件的 `schemaVersion` 管理颜色配置协议。

`theme.json` 使用以下格式；示例列出 v1 的全部颜色字段。`schemaVersion`、`base`、`appearance` 和 `colors` 必填。`colors` 支持稀疏覆盖，未提供的字段从内置基线补齐。`base` 在 v1 只接受 `mikutv-dark`，不引用其他可卸载主题，不引入主题依赖链。`appearance` 为 `dark` 或 `light`，用于同步宿主及可跟随外观的系统界面；它不自动改写已解析的颜色。

字段按用途而非页面命名，整个前端只消费解析后的语义配置：

| 颜色组 | 用途 |
|---|---|
| `surface`、`text`、`border` | 全局背景、层级表面、正文和边界 |
| `accent` | 主操作、强调和对应前景色 |
| `focus` | 普通遥控焦点的底色、前景和轮廓 |
| `selected` | 选中态及选中后聚焦的独立前景、背景 |
| `hover`、`pressed`、`disabled` | 指针悬停、按下和禁用控件的成对颜色 |
| `status` | 错误、警告和成功状态的成对颜色 |
| `overlay` | 遮罩、播放器渐变端点和阴影 |
| `playback` | 真实画面上固定对比度的控制、轨道和字幕颜色 |
| `decoration` | 环境渐变及无封面卡片背景的端点 |

颜色仅接受 sRGB 的 `#RRGGBB` 或 `#RRGGBBAA` 字面量，八位格式最后两位为 alpha。`border`、`overlay`、`decoration.ambient` 和 `playback.track` 可使用透明度，其他字段必须不透明。组件统一完成颜色解码、透明度合成和渐变，不读取 CSS 字符串、表达式或外部 URL。

`theme.json` 不超过 64 KiB。`colors` 至少覆盖一个字段；未声明字段从基线补齐，显式 `null`、未知字段、未知基线、非法外观值或不支持的版本均拒绝。修改 `background` 或 `foreground` 时必须同时提供对应状态的这两个字段；`selected.focusBackground`／`selected.focusForeground` 和 `accent.primary`／`accent.foreground` 同样成对。新增配置协议字段通过新的 `schemaVersion` 明确演进，不能依靠静默忽略拼错的字段。

宿主先将 sRGB 通道转换为线性亮度，再按 `(Lmax + 0.05) / (Lmin + 0.05)` 计算对比度。完整合并后执行下列门槛，任一失败则拒绝应用整个配置：

- 三档 `text` 对全部 `surface` 至少为 4.5:1。
- `accent.foreground` 对三档强调背景，以及 `focus`、`selected`、选中后聚焦、`hover`、`pressed` 和三种 `status` 的前景／背景组合至少为 4.5:1。
- `focus.ring` 对 `surface.canvas`、`surface.panel` 和 `surface.raised` 至少为 3:1。
- `playback.foreground` 和 `playback.secondary` 对播放器上下叠层在白色视频上合成后的颜色至少为 4.5:1，字幕与其描边至少为 4.5:1。

`disabled` 用独立成对颜色表达禁用状态，不参与正文对比度门槛。对比度校验完成后仍需在实体电视检查图片上的轮廓、渐变和观看距离下的可读性。

配色是 v1 的扩展范围，字体、字号、布局、间距、动效和焦点导航继续由宿主组件定义。封面、视频和品牌图像的固有像素颜色不作为 UI token 重写。默认内置基线从现有定稿按用途提取，迁移时以原画面对照，不能借提取配置改变已批准的视觉。

### 7.2. 主题选择与生命周期

主题选择属于全局外观偏好，与当前内容源、入口和账号无关。可以安装多个主题，一次只应用一个；安装完成后保持当前主题，在外观设置中确认选择才切换。内容源切换不重置主题，主题切换不改变内容源会话。

外观设置通过调色盘选择已安装主题，调色盘展示主题的实际配色。发现更多主题进入统一插件搜索目录，预选主题种类且只列未安装项。从选择器发起安装后返回原选择器，聚焦新安装的主题，保留原来的选中项；用户确认才应用。取消或逐层返回时恢复原来的页面、搜索条件和焦点。

主题的启用等同于选为当前全局主题，管理页与外观设置读写同一个主题选择。未选中的主题保留已安装状态，不维护多个主题同时启用的状态；停用当前主题等同于恢复内置基线。插件注册表保存公共包信息，各种类分别管理内容源启停和主题选择。

宿主在应用前完整解析、补齐并校验主题，构造不可变配置，在 UI 线程一次替换并重绘；不重建路由、播放或账号，也不丢失当前焦点。解析失败保留当前主题，更新失败保留原包和原配置。

更新正在使用的主题时，先验证新配置，成功后原子替换包与配置；原生界面不应经历半套新旧颜色。停用或卸载当前主题时回到内置基线，启动时已选主题缺失、损坏或不兼容也回到基线；这些操作不影响内容源或播放。宿主始终内置默认主题，其可用性不依赖插件下载。主题加载实现前，目录可显示该种类及不兼容原因，不能安装或启用为内容入口。

## 8. 请求、认证与资源

认证是来源插件的独立服务。插件负责账号状态查询、开始认证、轮询、取消、刷新和退出的具体协议；宿主提供通用状态流转、挑战展示与持久化能力，不请求网站登录端点或解析网站认证结果。

宿主按插件声明的认证方式选择已实现的 visual 组件，页面不根据插件 ID 分支。首版只实现既定扫码界面，不提供通用账号密码表单，也不把系统文本输入能力视为已经支持认证表单。

插件给出当前二维码挑战、有效期和认证进度；宿主展示等待、已扫码、过期等状态，再调用对应插件继续认证。取消、过期和重新开始都使旧挑战失效，认证凭据不进入普通页面状态或日志。

示例内容源插件使用这套服务实现扫码申请、轮询、账号校验和凭据刷新。二维码是该插件选择的认证方式，宿主核心保持通用。

普通配置与凭据分开存储，凭据通过宿主管理的 Keychain 按插件、入口实例和账号隔离。登录状态保存在本机，不依赖自建云端或登录态云同步。重启后由所属插件校验或刷新凭据，退出登录清除对应凭据。一个会话的刷新请求合并执行，旧账号的回调不得清除或覆盖新账号状态。

宿主为插件提供受控 HTTP、计时器、存储和必要的通用摘要能力。插件运行在独立事件循环上，网络和脚本执行不阻塞 UI 主线程，并具备取消、超时和内存限制。

图片、视频、字幕等由宿主获取的资源也携带入口所属的请求上下文。资源传输层按目标主机应用所需请求头，重定向时重新判断授权范围；不能把一个入口的 Cookie 或令牌带到另一个入口。页面和普通缓存不保存原始凭据。

直播阶段按需补充受控的长连接桥接，连接和订阅必须随所属入口关闭。

## 9. 播放边界

插件负责获取和更新播放计划，包括资源位置、分轨信息、字幕、过期时间和来源相关限制。宿主负责选择实际可播放的方案，建立原生播放器，并管理播放、暂停、拖动、画面叠层和前后台。

播放计划需区分直链、HLS 和音视频分轨资源，不能统一简化成一个 URL。协商需同时考虑客户端的容器及编解码能力、账号权限与内容限制。

音视频字节不经 JS 中转。到期续签通过插件完成；新的资源只能更新对应播放会话。进度和心跳通过统一事件交给插件，由插件转换成网站请求。

第一个真实 UGC 播放功能就验证流格式、音画、鉴权、过期和生命周期，避免等页面齐全后才检验播放可行性。

## 10. 错误与写操作

协议区分不支持、需要登录、权限限制、资源失效、网络错误、限流、取消和插件执行失败。页面按错误类型决定引导、重试或状态呈现，不解析网站错误码或错误文案。

写操作的超时不代表服务端没有执行。能够查询状态时先核对结果；支持等操作不自动重复提交。入口切换后，写操作结果仍归属于原入口，不能更新新入口的按钮状态。

插件异常应限制在当前入口，宿主保留切换入口与恢复的能力。

## 11. 收录、分发与安装更新

### 11.1. 插件目录

可收录插件使用独立 GitHub 仓库。作者添加 `mikutv-plugin` topic 后，宿主通过 `topic:mikutv-plugin archived:false` 查询生成可发现目录，展示仓库、作者、说明和安装状态。

目录按仓库身份去重，处理分页并缓存最近一次成功结果。离线、限流或刷新失败时保留缓存并呈现刷新状态。目录收录只提供发现信息，安装前仍需校验插件包。用户也可输入 GitHub 仓库地址安装。

插件管理是宿主的独立功能模块，页面呈现在既有设置框架的内容区，保留全局主导航与设置分类；不另开全屏管理窗口。已安装、发现、详情与操作复用既有列表、整行焦点和确认弹层。列表聚焦只移动焦点，确认后进入插件详情；日常入口切换从主侧栏的「切换入口」项完成。返回逐层关闭输入、确认或详情，并恢复原操作位置和焦点。

管理页只列已安装插件，负责查看、更新、启停与移除；发现页只列未安装插件，提供共用系统输入的名称／仓库搜索与种类筛选。详情返回时保留查询、筛选、列表位置和原焦点；空结果提供清除搜索或返回原页面的出口。

插件管理面向全部插件种类，列表和详情显示种类及兼容状态；入口页只列出已安装且启用的内容源实例。主题从外观设置选择，不产生内容入口。两者沿用同一套 visual 组件。

### 11.2. 发布与版本记录

插件仓库以正式 Release 发布 `plugin.zip`，包根目录包含 `plugin.json` 和种类要求的文件：内容源带入口 JS，主题带主题 JSON，两者均可携带展示资源。TypeScript 在发布前转成 JS，插件包不包含平台可执行程序。

从独立仓库安装和更新时，仅消费非草稿、非预发布的 Release，不回退到默认分支。宿主记录仓库、Release 标识、tag、资产标识及包的 SHA-256；清单版本应与发布版本一致。一次安装或更新使用已展示的同一份发布信息，避免下载时重新解析最新版本。

示例内容源插件的源码位于 `plugins/sample-source`，随应用构建成相同格式的插件包放入 `assets/plugins`，记录宿主发布版本、源码提交和包摘要。内置插件同样经过清单、导出和能力检查；宿主通过统一运行时调用，不为其提供绕过协议的业务路径。

### 11.3. 安装与更新

宿主下载至暂存目录，校验包结构、解压范围、公共清单、种类、宿主最低版本、协议版本及展示资源边界。内容源继续校验导出操作，编译检查时不执行插件；主题按第 7.1 节校验配置，不启动 moejs。已有预期摘要时需同时校验下载包的一致性。

安装前展示插件身份、种类、版本及所需权限，由用户确认。校验通过后原子写入插件目录，记录来源；内容源提供入口配置，主题提供外观选择，不在安装后自动应用。同一插件 ID 已绑定的仓库不能被另一仓库的包覆盖，也不能通过更新改变种类。

内容源安装成功后提供「选择入口」，进入选择页时聚焦新入口，但当前内容源保持不变；确认该卡片后才切换。也可结束安装并继续管理已安装插件。主题从外观选择器安装时按第 7.2 节返回原选择器；从普通插件目录安装时保留在已安装管理中，不自动应用。

独立安装插件从已记录的原仓库查询正式 Release，展示新版本后由用户执行；示例内容源插件随应用发布更新。扩大权限时重新确认；下载或校验失败保留原版本。替换当前使用的内容源前，先停止其播放、请求和运行时，再加载新版本；入口配置与账号数据保持所属关系。主题更新遵循第 7.2 节，不终止内容源请求和播放。

用户安装的插件可以卸载，随应用预装的内容源可以停用。移除内容源时关闭其运行时与任务，并移除对应入口；账号数据的保留与清理分开处理，不影响其他插件或入口。主题移除只影响该主题及必要的默认主题恢复，不清理内容源数据。

## 12. 验收约束

- 用同一套模板接入常规视频、电影和剧集集合数据，验证模型不依赖特定来源字段。
- 用缺少评论和弹幕的测试插件验证模块、导航、焦点项都被移除。
- 验证侧栏切换不同插件与头像切换当前插件账号的分工；确认才切换、取消返回、登录态复用、过期和停用当前插件后的去向。
- 验证切换入口、切换账号、取消请求后，晚到响应不会污染当前界面、观看记录或凭据。
- 验证异步网络、超时及脚本异常不会阻塞 UI。
- 用测试插件验证认证声明与宿主支持类型的匹配，不支持的认证方式不能安装或启用。
- 验证目录分页、缓存和刷新失败，确认未安装的插件不会出现在入口页。
- 验证已安装管理与未安装搜索的分工、系统输入、种类筛选、无结果出口，以及详情返回后的查询和焦点恢复。
- 验证内容源安装成功到入口选择的完整路径，新入口聚焦不触发切换；主题安装返回原调色盘，聚焦新主题不触发应用。
- 验证管理列表显示插件种类，入口只包含可用的内容源；缺失、未知和未实现的种类不能误作内容源加载，更新不能改变种类。
- 验证封面离线可用、缺失或损坏回退、裁切和焦点边界；拒绝包外资源路径，图片失败不影响选择与返回。
- F01 起检查组件统一取用主题配置，默认主题与定稿一致，焦点和选中前景／背景成对。
- 主题实现时验证稀疏覆盖、版本与字段校验、透明度、对比度、原子应用、失败保留及卸载恢复；主题切换不改变内容源、账号、路由、播放和焦点。
- 验证预装插件离线可用，安装包版本与摘要可追溯，安装和更新失败保留已有版本。
- 验证不兼容版本、来源冲突、权限扩大和插件移除的处理，配置与凭据不跨入口使用。
- 先完成示例影视真实登录和播放闭环，再按功能增加服务。
- 应用运行与视觉验收使用实体 Apple TV，不使用模拟器。

# 功能实施顺序与提交拆分

本计划基于现有 tvOS 基础、[插件化设计](plugin-architecture.md)和[既定 visual](visual/)。F01 已完成，F02 至 F48 待实施。编号表达功能依赖顺序，不对应 Git 提交总数。

## 1. 实施与提交规则

- 每个任务形成一个功能提交，包含该功能所需的页面、插件请求、状态处理、必要平台补丁和测试。
- 示例内容源插件的实现放在 `plugins/sample-source`，先遵循统一协议，再逐项接入网站功能；宿主只通过插件接口调用。
- 一个功能纵向打通后再推进下一项，页面与请求代码仍按插件化边界分别维护。
- 前端从 F01 起使用统一语义颜色配置，默认主题保持既定 visual；背景、文字、强调、边框、焦点、选中、状态、播放器叠层和阴影颜色不散写到组件。内容源与主题按 `kind` 区分，共用包管理。
- 共享选择弹窗从当前选项开始聚焦，关闭复用次级按钮；评论、通知与聊天区域使用焦点底色，不加沿圆角弯折的单侧强调线。
- 侧向面板推移正文，不遮盖正文：左侧导航展开时向右推，右侧评论面板展开时向左推，关闭后复位。平移保持正文布局宽度与滚动、焦点状态，避免展开过程中挤压重排。左右区域使用同一横向布局，正文固定宽度且不收缩，由侧栏宽度过渡自然推开正文，避免另行同步正文位移动画。侧栏展开使用图标与品牌名横排，收起只显示图标。
- 功能在实体 Apple TV 上验收通过后 commit、push。既有历史保留，后续功能普通追加提交。
- 任务内可做必要的局部修复，不顺带合入无关功能或整体重构。
- 临时截图在讨论中用于评审，验收结论写入提交说明；开发日志、凭据和临时验收产物不作为项目文档归档。

## 2. 第一阶段：完整的最小播放闭环

这一阶段按 F01 至 F06 顺序完成。结束后能在真实 Apple TV 上完成“选择入口 → 登录 → 推荐 → 详情 → 播放”。

| 任务 | 独立功能提交 | 内容与验收 |
|---|---|---|
| F01 | 入口选择与应用框架 | 先按架构第 7.1 节建立 `internal/theme` 的类型化语义颜色配置和内置基线，组件统一取色，迁移不改变既定 visual。沿用 visual 建立入口页、主导航、路由和公共状态组件；侧栏独立的「切换入口」用于切换内容源，头像用于当前入口内的账号切换，插件管理保留在设置框架内。入口卡片支持包内封面、缺图回退与当前标记。验证遥控焦点、方向导航、滚动、Back 层级与焦点恢复；覆盖确认选择、取消、最近入口恢复与无可用入口的去向。为后续页面提供框架，不在页面中接网站请求。 |
| F02 | 插件内核与内容源加载 | 建立公共清单、`kind` 分派和资源校验，再接入固定发布 tag 的 moejs、中立模型、操作注册、认证声明、能力识别、入口实例和受控宿主 API。按种类校验，不能将未知或尚未支持的 `theme` 当内容源执行；内容源专属字段不成为主题清单的必填项。接入内置内容源包，在真机验证加载、异步请求、取消、异常、切换、能力隐藏、集合数据和晚到结果；拒绝未支持认证声明及越界资源。固定内置包版本、源码提交和摘要，确认封面和插件离线可加载。 |
| F03 |示例内容源扫码登录 | 内置插件通过统一认证服务实现扫码申请、轮询、账号状态、凭据刷新和退出；宿主按 `qrCode` 声明使用既定 visual 并隔离持久化。验证等待、已扫码、过期、取消、刷新二维码、旧轮询失效及重启恢复；切换插件复用所属登录态，当前插件的账号切换与其他插件会话隔离，登录过期不影响其他入口。到本项再请用户扫码，确认真实账号和后续请求所需凭据有效。 |
| F04 | 推荐 | 接入真实推荐、分页、刷新、错误和重试。卡片通过统一模型呈现，列表状态和焦点稳定，切换入口后旧结果不覆盖新界面。 |
| F05 | 视频详情 | 从推荐打开真实详情，呈现标题、封面、简介、创作者及内容权限。操作按能力显示，返回时恢复原列表位置和焦点。 |
| F06 | 基础 UGC 播放 | 插件解析播放计划，宿主接入原生视频与 Go 控制层。使用真实视频验证流格式、请求头、音画、暂停、拖动、资源过期处理及前后台。确认从推荐经详情进入播放的完整链路。 |

F03 的扫码验收通过后再推进依赖账号的功能。F06 通过后再扩展播放器菜单和其他播放类型，避免先完成大量页面、最后才检验播放可行性。

## 3. 第二阶段：系统输入与插件管理

| 任务 | 独立功能提交 | 内容与验收 |
|---|---|---|
| F07 | 系统文本输入 | 接入 tvOS 系统输入及结果回传。验证打开、提交、取消、输入结束后的焦点恢复，为搜索和发送类功能提供统一编辑入口。 |
| F08 | 插件目录 | 通过 `mikutv-plugin` topic 查询可收录仓库，在既有设置框架内区分已安装管理与未安装发现。发现页共用系统输入搜索名称／仓库，提供种类筛选与无结果出口；详情返回恢复查询、筛选、位置和焦点。展示种类、来源、兼容性与安装状态；种类以选定 Release 的清单为准，不能按仓库名称猜测。验证分页、去重、缓存、离线与限流恢复；目录条目不自动成为入口，主题不出现在内容入口页。 |
| F09 | 插件安装 | 从目录或输入的 GitHub 仓库地址选择正式 Release，下载并按种类校验 `plugin.zip`，确认身份、种类、版本及权限后安装；当前支持的内容源再配置入口，尚未实现的种类按不兼容处理。成功后提供入口选择并聚焦新入口，确认前保留当前内容源，也可结束安装后继续管理。验证摘要记录、资源路径、协议与认证方式不兼容、同 ID 来源冲突、取消、失败清理及安装后的完整返回与选择路径。 |
| F10 | 插件更新 | 从原仓库检查正式 Release，固定所选版本与摘要后更新；示例内容源随应用更新。验证禁止改变种类、权限扩大时重新确认、失败保留原包；内容源更新停止其播放和请求，保持实例配置及账号归属。包更新按种类回调，不让主题更新经过内容源停播流程。 |
| F11 | 插件移除 | 实现已安装插件卸载与内置内容源停用，按种类处理生命周期。移除内容源时关闭其运行时、播放和请求并移除入口；验证账号数据保留与清理范围。停用当前内容源后返回入口选择，无入口时仍可管理插件；主题移除的默认恢复由 F45 接入，不清理内容源会话。 |

先完成 F01 至 F06 的预装插件播放闭环，再接入目录和包管理。F07 为手动填写仓库地址提供系统输入；插件管理按目录、安装、更新、移除依次提交。

## 10. 依赖与验收重点

- F01 从首次写前端就提取完整语义配色并验证默认视觉一致；同时解决实际遥控导航与返回，不能把单个确认键当作完整导航能力。
- F02 先定义公共插件协议、种类、资源边界及内容源的认证声明、运行时和能力隐藏；示例影视是内置内容源，网站请求从第一天就进入插件。主题格式已经确定，加载与选择在 F45 实施，此前按不兼容处理。
- F03 需要用户扫码参与，扫码界面成功后还要以真实账号接口核验凭据和恢复行为。
- F06 提前检验真实流格式与播放能力，插件拿到 URL 不等于宿主可以播放。
- F08 至 F11 复用 F02 的包格式、来源记录和兼容性校验，不以目录请求成功替代真实安装、更新和移除验收。
- 当前只支持插件声明 `qrCode` 认证。账号密码表单和设备码不在可声明类型中；F07 的文本输入不开放新的认证方式。
- F07 先于搜索、评论、弹幕和私信编辑；F19 先于复杂的连续观看；F21、F33、F34 先于 F35。
- 点播、状态恢复和权限处理稳定后，再扩展番剧、直播、课堂和互动分支。
- 每个新增可选功能都通过缺少该能力的测试源检查布局和焦点，不把特定来源功能默认开放给所有入口。

逻辑测试重点覆盖分页、取消、入口与账号切换、晚到结果、权限和写操作状态。UI 测试检查交互后的行为与状态，不通过重复文案列表或默认值来证明功能正确。运行、播放、视觉和遥控验收均使用实体 Apple TV。
